Laptop moverPassword

The password step

Every part is encrypted with 7-Zip (AES-256, file names too). Type a long passphrase twice. It goes from this page straight to 7-Zip through a pipe: it is never on a command line, in a file, in a log or in an address, and the mover keeps no copy. Write it down somewhere safe: without it the bundle cannot be opened, and nobody can recover it.

Run the dry run first: packing uses its output folder and part size.

At least 12 characters

Letters, digits, spaces and the signs of a US keyboard only (no accented letters), so it types the same on any keyboard

Laptop moverNew laptop: restore

On the new laptop: restore

  1. Download the kit zip and all parts into one new folder, for example C:\move.
  2. Unzip laptop-move-kit.zip there.
  3. Open PowerShell in the unzipped kit folder and run the command below. Do not change the execution policy.
.\node.exe kit.mjs ui

Without a page: .\node.exe kit.mjs restore --from C:\move (7-Zip then asks for the password in the console).

This is the old laptop: the restore runs on the new one, from the unzipped kit. The form below still checks a bundle folder.

Laptop moverTutorial

Tutorial: your first move in 5 steps

  1. Scan. The mover lists folders, applications, settings and repositories. Nothing is changed.
  2. Choose. Tick what moves. Client repositories with a remote stay out.
  3. Pack. Type a password twice in the page. Keep it safe: it is not stored.
  4. Upload. Put the bundle on your Accenture OneDrive yourself.
  5. Restore. On the new laptop download the bundle, start the mover and restore.
Tip: run the dry run first. It shows size, parts, time and the route of every app.
Laptop moverInstructions

Detailed instructions: restore on the new laptop

  1. Download the kit zip and all parts into one new folder, for example C:\move.
  2. Unzip laptop-move-kit.zip there. It holds the mover, the manifest, a README and the signed node.exe.
  3. Open PowerShell in the unzipped kit folder and run the command shown below. Do not change the execution policy.
  4. In the page that opens, check the bundle first, then type the password and restore.
  5. Read the report. Do the by-hand list. Clone the client repositories after you push them.
.\node.exe kit.mjs ui
If a checksum failsDownload that part again. Never unpack a part that failed its check.
If an app install is refusedThe signature did not match the recorded publisher. Install that app from the vendor's own page.
If 7-Zip says the password is wrongType it again with care for capital letters. The password cannot be recovered.

FAQ

Is my password stored anywhere?No. You type it into this page; it goes to 7-Zip through a pipe and is never stored, logged or put in a command line, a file or an address.
Where do I upload the bundle?To your Accenture OneDrive only. Never a client's OneDrive, never a personal drive.
What about client repositories?With a remote: they stay out, you push first and clone again. Without a remote: a separate encrypted client part for your Accenture OneDrive only.
Are printers and Wi-Fi moved?No. Secure print queues come from the company setup on the new laptop: check that one page prints. No Wi-Fi profile or key is packed: check that the office network is there.
Does it change my repositories?No. It does not push or fetch and reads git without locks.
