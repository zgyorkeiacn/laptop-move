Security notes for IT

This page describes what the laptop mover reads, writes and never touches, so that IT can review it. The mover is a small Node.js program with no outside dependencies. Its source is in the repository and its tests run offline.

Summary

QuestionAnswer
What does it do?Packs chosen folders, repository state, settings and an application list into encrypted parts on a local folder, and restores them on another laptop.
Does it upload anything?No. The user uploads the bundle to their Accenture OneDrive by hand. The tool never writes into a OneDrive folder or a client's folder.
Are credentials moved?No. Secret-bearing files and folders are never copied, even if ticked. They are listed for the user to set up again.
Does it read the OS secret store?No. It does not use DPAPI, Windows Credential Manager, cmdkey, keytar or the Keychain, and it exports no Wi-Fi profile or key.
Does it bypass anything?No. It needs no administrator rights, never changes the execution policy and never starts PowerShell with a bypass. Its PowerShell calls use -NoProfile -NonInteractive and only read a file's signature.
What executables does it run?The signed portable node.exe shipped in the kit (or the user's own Node), the installed 7-Zip 26.03 or newer at C:\Program Files\7-Zip\7z.exe, git, winget, reg and Windows PowerShell for signature checks. Vendor installers run only if the Authenticode signature is valid and matches the publisher recorded at packing time.
Encryption7-Zip AES-256 with encrypted file names. One password for all parts, typed by the user twice in the page.
IntegritySHA-256 of every part, recorded at packing and checked before anything is unpacked.

What it reads

  • The folders and repositories the user ticked, and the scan roots the user gave (default: the user folder and the system drive, names and sizes only).
  • Git state, read only: branches, remotes, unpushed commits, stashes, uncommitted files. Git runs with optional locks off and never fetches, pulls, pushes or changes a ref on the old laptop.
  • The list of installed applications from winget list, and the user's PATH from the registry (reg query).
  • The selection file and the local client rules file, if present.

What it writes

  • Old laptop: the bundle folder the user names, with its own staging folder; the selection file if the user saves it, with a dated .bak.json copy of an older one. Nothing is deleted or changed in the user's folders or repositories.
  • New laptop: a work folder for unpacking; the restored folders, settings and repositories at their original paths; backups of any file it replaces; junctions; an HTML report. If it installs a portable tool, it adds that folder to the user's PATH (HKCU\Environment) and nothing else in the registry.
  • Applications installed through winget or a signed vendor installer, with the user's own rights.

Network

  • The page: served on 127.0.0.1 only, on a free port, behind a one-time link that is swapped for an HttpOnly, SameSite=Strict cookie, plus a per-session key header. Requests with another Host or Origin are refused. A strict content security policy allows only the page's own files, with no outside scripts or fonts. The mover stops when the page closes or the user presses End.
  • Old laptop: none started by the tool, apart from winget's own lookups if the user asks for the application list.
  • New laptop: winget, git clone from the repositories' own remotes (the user signs in through Git Credential Manager), and, for a few tools, a vendor download over https that is checked against the vendor's published checksum and signature.
  • The tool uploads nothing, and sends no telemetry.

The password

The user types it into the page. The page sends it to the mover on 127.0.0.1, and the mover pipes it to 7-Zip's standard input. It is never on a command line, in a file, in a log or in an address, and the mover keeps no copy after the step. It is never uploaded, and it cannot be recovered: if lost, the bundle cannot be opened. Without the page, 7-Zip asks for it at its own console prompt and the mover never sees it.

Client data

  • Client repositories with a remote stay out of the bundle.
  • Client folders and repositories without a remote go into a separate encrypted client part for the user's Accenture OneDrive only.
  • The tool refuses to write its output into a client folder or a client's OneDrive, as set in the local client rules file. The tool itself names no client.

What it never touches

  • Credentials of any kind, the Windows secret store, browser profiles and passwords, saved Wi-Fi keys.
  • Other users' folders, system settings, services, scheduled tasks, firewall, drivers and policies.
  • The execution policy, UAC, or any administrator-only setting.
  • A client's OneDrive or any cloud drive other than the user's own Accenture OneDrive, which the user, not the tool, uses.

Review it yourself

The repository holds the source and its tests (npm test), and a check that drives the page in Edge on sample data. Run the dry run to see exactly what would be packed, with nothing written.
