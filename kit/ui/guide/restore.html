New laptop: restore

Do this on the new laptop, signed in as yourself. You do not need administrator rights for the mover itself, and you must not change the PowerShell execution policy: nothing here needs it. Only when a folder the restore puts things into may not be made by you (a folder directly on C:\, on some laptops), Windows asks once for permission to make it.

Get the files

  1. Download the kit zip and all the parts from your Accenture OneDrive into one new folder, for example C:\move.
  2. Right-click laptop-move-kit.zip and choose Extract All, into the same folder. You get a laptop-move-kit folder with node.exe inside.
  3. Open PowerShell in that folder (in File Explorer, right-click in the folder and choose Open in Terminal).
  4. Start the mover:
.\node.exe kit.mjs ui
If company policy blocks the bundled node.exe, install Node from Software Center or with winget, then run node kit.mjs ui instead.

Check, then restore

  1. The page opens on the restore screen and shows what the bundle is: where and when it was packed, and how many parts.
  2. Fill Folder with the downloaded parts (C:\move) and Work folder for unpacking (a local drive with room, about 1.3 times the bundle size).
  3. Press Check first (nothing is written). It checks every part against its checksum and the free space, and shows what the restore would do. Fix anything under Fix these first.
  4. Tick the options you need: Skip the applications, Skip the client part, or Overwrite files that already exist. By default a file that already exists is kept and listed as a conflict.
  5. Type the bundle's password and press Restore now. Confirm the question.

While it runs

The page moves to Restore progress. The mover works in this order:

  1. 7-Zip first, because the parts cannot be opened without it: installed for you if it is missing (with winget, else with the installer recorded on the old laptop).
  2. Check the checksums, then unpack the parts.
  3. Make the folders the restore puts things into, before anything goes into them. If one of them needs administrator rights, Windows asks you once.
  4. Install the applications one by one.
  5. Clone the repositories again and put back their local commits, stashes and files.
  6. Put the folders and settings back at the same paths, and recreate the links.

Choose how you see it with the switch at the top: Steps lists the steps and the messages, Dashboard shows each step's count and bar, what runs now and for how long, and every problem so far. Your choice is kept for the next time.

An application is installed only when its signature is valid and matches the publisher recorded at packing time.

Every step has a time limit: 30 minutes for an install, a clone or a download (three times as long for Visual Studio Build Tools). A step that is not done by then, for example an installer waiting for an answer, or a sign-in window nobody saw, is stopped, written down, and the restore goes on with the next one. The report lists what was stopped, under Timed out. Everything is written to restore-log.txt in the work folder as it happens. If the restore stops, run it again: it continues where it stopped.

Without the page

.\node.exe kit.mjs restore --from C:\move --dry-run
.\node.exe kit.mjs restore --from C:\move

7-Zip then asks for the password in the console. When the parts are unpacked, the dashboard opens in a window of its own, on top of the others, and shows where the restore stands. Closing it never stops the restore; .\node.exe kit.mjs dashboard opens it again, and --no-dashboard leaves it closed. --step-timeout 60 gives every step 60 minutes instead of 30.

To try a restore without touching real places, add --target-root C:\LaptopMove\trial --skip-apps.
