Before the move

Do these on the old laptop, in this order. Most of the later trouble comes from skipping one of them.

1. Push your repositories

The mover does not push or fetch, and it never changes a repository. A repository with a remote is cloned again on the new laptop, so what is not on the remote must be pushed first, or it travels as a local bundle.

  • For every repository you care about, push the branches you work on.
  • Unpushed commits and stashes still travel in the bundle as a safety net, but a pushed branch is the safe copy.

2. Client repositories and the client part rule

Client data is never mixed with the rest, and never leaves Accenture's own space.

  • A client repository with a remote stays out of the bundle. The dry run lists it under Push first. Push its work, then clone it again on the new laptop.
  • A client repository without a remote, or a client folder, goes into a separate encrypted client part, client-*.7z.*. Upload that part to your Accenture OneDrive only.
  • Never put any part on a client's OneDrive (its folder name usually carries the client's name) or on a personal drive. The mover refuses to write its output into a client's folder or OneDrive.

Which folders and remotes count as client data is set in a small local file, laptop-move-client.json, next to your selection file. Ask your project lead if you are unsure; without the file the mover stops, unless you confirm that nothing on this laptop is client data.

Client rules file. The mover itself names no client. The file lists client folders and remote address patterns, and the folders where output must never be written.

3. Know your secrets: the by-hand list

These are never copied. Make your own list now, and set each up again on the new laptop yourself, the safe way for what it is:

ItemWhat to do on the new laptop
SSH keys (.ssh)Create new keys, or restore them from your approved secret store, and register the new public key again.
.env files and tokensCreate the values again from their source. Do not email or upload them.
.npmrc, .pypirc, Maven settings.xmlSign in to the registry again and create a new token.
Cloud credentials (AWS, Azure, kube)Sign in again with the company tool.
Browser loginsSign in to Edge and Chrome with your account and let them sync. Profiles are never copied.
Git credentialsGit Credential Manager asks you to sign in the first time you clone from each host.
Certificates and password vault filesImport them again from where you keep them.
PrintersCheck that your secure print queue is there and that one page prints.
Wi-FiThe office network usually comes with the company image. Check it, and join other networks by hand.

The page builds this list for you from your selection and from the files the dry run finds. You tick each item when it is done.

4. Time and space

  • Space on the old laptop: a local folder (not a OneDrive folder) with room for about the size of your chosen data, a little more to be safe. The dry run shows the exact size.
  • Space on the new laptop: room for the downloaded bundle, plus a work folder of about 1.3 times the bundle size on a local drive. The restore checks this and says so before it starts.
  • Time: the dry run estimates packing, upload (at 10 MB per second) and unpacking. For a few GB it is minutes; for tens of GB expect a long lunch. Plug both laptops in.
  • Tools: 7-Zip 26.03 or newer (installed at C:\Program Files\7-Zip\7z.exe). On the new laptop the restore installs it for you if it is missing.
Tip. Close big programs before packing, and do not work in the folders while they are being packed.
